ebpf-lab/예제 05/XDP

드라이버 최전선

지금까지는 전부 "관찰"이었다. XDP부터는 반환값이 패킷의 운명을 결정한다. 커널 네트워크 스택이 시작되기도 전에 실행되기 때문에 가장 빠르고, 그만큼 제약도 많다. Cilium의 DDoS 드롭과 로드밸런싱이 서 있는 자리다.

00XDP란 무엇인가

skb가 만들어지기 전, 드라이버가 패킷을 받은 그 순간.

얼마나 앞인가

리눅스가 패킷을 받으면 보통 sk_buff(skb)라는 구조체를 할당하고 거기에 메타데이터를 채운다. 그 다음에야 netfilter, tc, 소켓 계층이 돌아간다. XDP는 이 skb 할당보다 앞이다. 

NIC → 드라이버 → [ XDP ] → skb 할당 → tc/TCX → netfilter → 소켓
                    ↑
                    여기서 DROP 하면 skb 할당 비용조차 안 든다

그래서 DDoS 방어에 압도적이다. 버릴 패킷에 대해 아무 비용도 치르지 않는다. iptables로 드롭하면 이미 skb를 만들고 스택을 태운 뒤다.

반환값이 곧 결정이다

반환값결과쓰임
XDP_PASS정상 스택으로 넘긴다관찰만 할 때 (이 랩)
XDP_DROP즉시 버린다DDoS 방어 (11번 게임)
XDP_TX들어온 인터페이스로 되쏜다로드밸런서 응답
XDP_REDIRECT다른 인터페이스/CPU로 보낸다Cilium 파드 간 전달
XDP_ABORTED버리고 추적점 발생버그 신호 — 정상 경로에 쓰지 말 것

세 가지 모드

  • native — 드라이버가 직접 지원. 제일 빠르다.
  • offloaded — NIC 하드웨어에서 실행. CPU를 아예 안 쓴다(스마트NIC 필요).
  • generic(SKB) — 드라이버 지원이 없을 때 커널이 흉내낸다. 느리지만 어디서나 된다. 이 랩은 veth라 generic 모드로 붙인다.

01이 랩이 하는 일

판단하지 않고 세기만 한다. 항상 XDP_PASS.

수신 패킷을 프로토콜별로 집계한다. 반환값은 언제나 XDP_PASS — 즉 트래픽에 아무 영향이 없다. 11번 게임에서 같은 자리에 XDP_DROP을 넣으면 방어가 된다.

맵은 PERCPU_ARRAY다. 패킷 처리 경로에서 락이 있으면 안 되기 때문이다.

/* 슬롯 배치: IP 프로토콜 번호를 그대로 인덱스로 쓴다 */
6   = TCP      17  = UDP       1   = ICMP
256 = ARP      257 = IPv6      258 = 기타

프로토콜 번호(0~255)를 인덱스로 쓰고 그 위 구간을 특수 슬롯으로 쓰는 방식이다. 해시맵보다 배열 인덱싱이 훨씬 싸기 때문에 패킷 경로에서 자주 쓰는 패턴이다.

02경계 검사 — 이 랩의 진짜 주제

포인터를 직접 만지는 유일한 랩이다. verifier와 정면으로 만난다.

XDP는 성능을 위해 패킷 메모리를 직접 포인터로 준다. 헬퍼 경유가 아니다. 대신 verifier가 모든 접근에 대해 범위 안임을 증명하라고 요구한다. 

void *data     = (void *)(long)ctx->data;
void *data_end = (void *)(long)ctx->data_end;

struct ethhdr *eth = data;
if ((void *)(eth + 1) > data_end)   /* 이 줄이 없으면 로드 거부 */
        return XDP_PASS;

/* 여기부터는 eth 를 안전하게 읽을 수 있다 */
__u16 proto = bpf_ntohs(eth->h_proto);
읽는 법

eth + 1은 "struct ethhdr 하나만큼 뒤"라는 뜻이다. 즉 이 헤더의 끝 주소. 그게 data_end를 넘으면 패킷이 헤더보다 짧다는 뜻이니 읽으면 안 된다. 헤더를 하나 벗길 때마다 이 검사를 반복한다.

verifier가 거부할 때 읽는 법

invalid access to packet, off=14 size=20, R2(id=0,off=14,r=14)
R2 offset is outside of the packet

r=14가 "지금까지 증명된 안전 범위"다. 14바이트(이더넷 헤더)까지만 검사했는데 20바이트(IP 헤더)를 읽으려 한다는 뜻이다. r= 값과 읽으려는 크기를 비교하면 어느 검사가 빠졌는지 바로 보인다.

03함정과 다음 단계

XDP 특유의 제약들.

함정 1 · veth 에는 native XDP 가 없을 수 있다

컨테이너의 eth0은 veth다. Go 쪽에서 generic(SKB) 모드로 붙이는 이유가 이것이다. 프로덕션 NIC라면 native로 붙어 훨씬 빠르다.

함정 2 · XDP 는 ingress 만이다

나가는 패킷은 볼 수 없다. 양방향이 필요하면 TC/TCX(06번)를 써야 한다. 이게 XDP와 TCX를 가르는 첫 번째 기준이다.

함정 3 · 헤더 조작이 제한적이다

skb가 없어서 메타데이터가 거의 없고, 크기를 늘리려면 bpf_xdp_adjust_head() 같은 전용 헬퍼가 필요하다. 체크섬 재계산 헬퍼도 TC 쪽이 훨씬 풍부하다. 패킷을 고칠 거면 TC, 버릴 거면 XDP가 대략의 기준이다.

다음

06번은 같은 네트워크 훅인데 skb가 있는 자리다. 느린 대신 양방향이고 메타데이터가 풍부하다. 그리고 11번 게임에서 이 랩의 XDP_PASS 자리에 XDP_DROP을 넣어 SYN flood를 실제로 막는다.

A. O / X

01XDP 프로그램은 sk_buff가 할당되기 전에 실행된다.

정답 O. 드라이버가 패킷을 받은 직후다. 그래서 여기서 DROP하면 skb 할당 비용조차 들지 않는다 — DDoS 방어에 압도적인 이유다.

02XDP는 수신(ingress)과 송신(egress) 양쪽에 붙을 수 있다.

정답 X. ingress 전용이다. 나가는 패킷을 보려면 TC/TCX(06번)를 써야 한다.

03패킷 데이터에 접근하기 전에 data_end와 비교하는 경계 검사를 하지 않으면 로드가 거부된다.

정답 O. XDP는 성능을 위해 패킷 메모리를 직접 포인터로 준다. 그 대가로 verifier가 모든 접근이 범위 안임을 증명하라고 요구한다.

04if ((void *)(eth + 1) > data_end)에서 eth + 1은 이더넷 헤더의 끝 주소를 뜻한다.

정답 O. 포인터 산술이라 "구조체 하나만큼 뒤"다. 그게 패킷 끝을 넘으면 헤더가 다 안 들어온 것이니 읽으면 안 된다.

05XDP_ABORTED는 조용히 패킷을 버리는 정상적인 방법이다.

정답 X. 버리기는 하지만 추적점(tracepoint)을 발생시킨다. 버그 신호용이다. 정상적으로 버릴 때는 XDP_DROP을 쓴다.

06이 예제는 패킷을 세기만 하고 트래픽에는 영향을 주지 않는다.

정답 O. 항상 XDP_PASS를 돌려준다. 11번 게임에서 같은 자리에 XDP_DROP을 넣으면 방어가 된다.

07컨테이너의 veth 인터페이스에서는 native XDP가 항상 지원된다.

정답 X. 지원되지 않을 수 있어서 이 랩은 generic(SKB) 모드로 붙인다. 느리지만 어디서나 동작한다.

08프로토콜 카운터로 HASH 맵 대신 PERCPU_ARRAY를 쓴 이유는 락 경쟁을 피하기 위해서다.

정답 O. 패킷 처리 경로에는 락이 있으면 안 된다. 게다가 배열 인덱싱이 해시 조회보다 훨씬 싸다.

09verifier 에러의 r=14는 "지금까지 안전이 증명된 범위"를 뜻한다.

정답 O. 14바이트(이더넷 헤더)까지만 검사했다는 뜻이다. 이 숫자와 읽으려는 크기를 비교하면 어느 경계 검사가 빠졌는지 바로 보인다.

10패킷 헤더를 수정하는 작업은 XDP가 TC보다 편하다.

정답 X. 반대다. XDP는 skb가 없어 메타데이터가 빈약하고 크기 조정에 전용 헬퍼가 필요하다. 고칠 거면 TC, 버릴 거면 XDP가 대략의 기준이다.

11iptables로 드롭하는 것과 XDP로 드롭하는 것은 비용이 같다.

정답 X. iptables는 이미 skb를 만들고 스택을 태운 뒤다. XDP는 그 앞이라 버릴 패킷에 대해 거의 아무 비용도 치르지 않는다.

12IP 헤더를 읽기 전에도 이더넷 헤더와 별개로 경계 검사를 다시 해야 한다.

정답 O. 헤더를 하나 벗길 때마다 검사를 반복한다. 이전 검사는 그 헤더까지만 증명한다.

B. 빈칸 채우기

코드를 보지 않고 먼저 답해 보고, 눌러서 확인한다.

C1XDP에서 패킷 데이터의 시작과 끝을 얻는 필드는?
void *data = (void *)(long)ctx->____; 
void *data     = (void *)(long)ctx->data;
void *data_end = (void *)(long)ctx->data_end;

두 값의 차이가 곧 패킷 길이다. 모든 경계 검사가 data_end와의 비교다.

C2패킷을 즉시 버리는 XDP 반환값은? 
return XDP_DROP;

11번 DDoS 게임에서 이 자리를 채운다. 이 예제는 관찰만 하므로 항상 XDP_PASS다.

        return XDP_PASS;
count(ip->protocol, len);
